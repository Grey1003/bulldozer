# 推土机日频回测程序

本项目在你的电脑上运行 Python，通过 **BaoStock 免费接口**按需读取 A 股历史日线。没有行情 CSV、Parquet、SQLite 数据库，也没有行情磁盘缓存。运行时数据会经过网络传入本地内存；本地计算不可能完全不接收数据、不使用内存。本项目实现的是“不维护、不落盘行情数据库”。

数据源与回测分工：BaoStock 提供日线，pandas / NumPy 支撑本项目的日频账户与成交引擎。BaoStock 本身不是回测引擎。本项目没有绑定聚宽、米筐付费账户，也没有使用云端回测。没有交易下单功能。

## 1. 先运行

需要 Python 3.10 或更新版本。Windows 打开项目文件夹中的终端，macOS / Linux 同样适用。

```bash
python -m venv .venv
```

Windows PowerShell 激活：

```powershell
.venv\Scripts\Activate.ps1
```

macOS / Linux 激活：

```bash
source .venv/bin/activate
```

安装依赖：

```bash
python -m pip install -r requirements.txt
```

先用少量股票检查真实接口：

```bash
python bulldozer.py check --config quickstart.json
```

检查成功后，对示例股票运行真实历史回测：

```bash
python bulldozer.py backtest --config quickstart.json --segment test --output results_quick
```

`quickstart.json` 只有六只股票，用来排查接口、环境和输出流程。这些股票不是推荐标的，不代表全市场；严格图形条件下没有交易也完全可能，不应为制造交易而随意放松规则。

全市场回测：

```bash
python bulldozer.py backtest --config config.json --segment test --output results_full
```

训练、验证、冻结参数，再做一次最终测试：

```bash
python bulldozer.py tune --config config.json --output results_tune
```

离线合成数据演示，不需要访问行情接口：

```bash
python bulldozer.py demo --output results_demo
```

**demo 的价格全部是程序生成的，不是真实行情。为了验证流程，demo 会明确放宽部分选股参数；其收益绝不能作为策略有效性的证据。**

运行逻辑测试：

```bash
python -m unittest discover -s tests -v
```

## 2. 文件与输出

| 文件 | 作用 |
| --- | --- |
| `bulldozer.py` | 数据接口、信号、日频成交与账户、参数研究、命令行入口 |
| `config.json` | 完整参数；默认全市场 |
| `quickstart.json` | 小股票池、短区间的配置覆盖示例 |
| `requirements.txt` | Python 依赖 |
| `tests/test_engine.py` | 不依赖网络的关键交易语义测试 |
| `VALIDATION.md` | 本次交付的验证范围与未验证项 |

回测仅保存分析结果：

- `equity.csv`：每日净资产、现金、仓位、应收分红。
- `trades.csv`：买卖成交记录、手续费、卖出盈亏、买入限价和成交原因。
- `diagnostics.csv`：每天的候选数量、订单数、成交数、买入预算。
- `summary.json`：指标、期末未平仓、完整参数、依赖版本、源代码哈希及限制。

调参额外产生 `training_comparison.csv`、`validation_comparison.csv`、`selected_config.json`。测试结果在 `research/test`。

结果中保留的是交易价格和账户统计，不是用于再次回测的原始行情库。再次运行会重新请求服务端数据，结果也可能受供应商历史修订影响。

## 3. 日频版对原战法做了什么取舍

原 PDF 的集合竞价、9:40 截止、盘中高点卖出，都无法从一根日 K 线重建。本版本没有假装实现这些细节。

默认交易顺序：

1. 昨天收盘后，用截至昨天的日线判断是否入选，固定今天的买入上限。
2. 今天开始前冻结买入预算，不用今天晚些时候才卖出的资金回填早盘买单。
3. 昨日以前买入的普通持仓，今天开盘执行退出；开盘涨停可以按开关继续持有。
4. 预先确定的买单按日频限价模型匹配，今天买入的股票今天不能卖。
5. 若选择 `next_close`，旧仓按事先固定的次日收盘退出计划执行。
6. 收盘后更新市值；今日观察到的信息只允许影响以后交易日。

默认 `entry_mode=limit_touch`：买单有效期是一整个交易日，这是对原开盘低吸窗口的放宽。股票开盘价不高于委托价，按开盘限价匹配；高开后，日内最低价至少穿过委托价一个报价单位，才按委托价模拟成交。**最低价只用于匹配已经存在的买单，绝不用于当天生成买单。**

如果希望对成交条件更简单、更可解释，改成 `entry_mode=open_only`：只判断下一交易日开盘能否以不高于限价买入，不使用日内最低价触发买入。两种版本应单独对照，不能混在一起汇报收益。

日内穿价不证明真实排队能成交，默认有成交量占比上限。成交额和滑点都属于模拟假设。开盘成交用昨日成交量作为容量参考，日内限价成交用当日成交量作为撮合容量上界；这两种约束都不是逐笔订单簿模拟。

## 4. 选股规则对应代码的位置

这些阈值是量化近似的初始值，不是原作者给出的经过验证的最优参数。

| 文档概念 | 实现 | 主要配置 |
| --- | --- | --- |
| 普通 10% 股票 | 主板代码白名单、历史 ST 字段、最低上市交易日数 | `data.symbols`, `data.min_listing_sessions` |
| 均线向上、多头排列 | 5 日 > 10 日 > 20 日，且三条均线高于各自 5 日前 | `fast_ma`, `middle_ma`, `slow_ma`, `slope_days` |
| 连续沿五日线向上 | 近 8 日五日均线上升天数达到 8 天 | `trend_days`, `min_rising_days` |
| 贴线 | 实体下端 / 均线 − 1；8 天内至少 6 天在 −1%～5% | `min_touch_days`, `touch_min`, `touch_max` |
| 昨日不离均线太远 | 昨日收盘对快均线偏离在 0～6% | `close_bias_max` |
| 有活跃度 | 平均振幅 2%～8%；近 20 日至少一次收盘涨停 | `amplitude_*`, `limit_lookback`, `min_limit_count` |
| 不选近期连板回调 | 近 10 日出现连续 2 日收盘涨停则排除 | `consecutive_lookback`, `exclude_consecutive` |
| 不选昨日大涨 | 昨日涨幅不超过 6% | `yesterday_return_max` |
| 不选突然远离均线 | 实体贴线、昨收偏离共同限制；没有额外偷偷加入加速模型 | 同上 |
| 不选二波 | 历史窗口内先涨 20%、后回撤 10%、再反弹 8% | `first_wave_filter`, `wave_*` |
| 前高压力 | 可选，仅接近前高 ±5% 时排除二波 | `wave_mode=near_high`, `prior_high_band` |
| 可选流动性底线 | 平均成交金额；默认关闭 | `min_average_amount` |

表中未带组名前缀的参数都在 `strategy` 下。基础选股函数为 `make_signals`，二波近似为 `second_wave`，买价为 `buy_limit`。

“第一波”和“漂亮图形”不是完美可识别的客观类别。二波模块用过去数据按时间推进，不使用未来确认波峰、不回填信号。它仍可能误判，务必对照关闭模块的结果。

股票过多时，按贴线满足天数降序、昨日均线偏离升序、代码升序排列。排序不查看今天涨跌。每天最多对固定的前五只下单，不因另一只当天后来涨得好再替换候选。

## 5. 买价与复权

五日均线默认使用收盘价的简单平均。

设昨日为 d，预测今天均线时，用昨日收盘代替今天价格：

`预测五日线 = (C[d] + C[d-1] + C[d-2] + C[d-3] + C[d]) / 5`

上式 `C[d]` 出现两次是有意为之：一次作为昨天真实收盘，一次作为今天价格的预估。程序对可调整的 n 日均线做同样推广。

买价有两种模式：

- `buy_price_mode=offset`：`min(昨收, 预测均线×(1+buy_offset))`。
- `buy_price_mode=position`：`预测均线 + buy_position×(昨收−预测均线)`。

默认上浮 1.5%，价格向下取至 0.01 元，绝不超过昨收。若预测均线高于昨收，区间不存在，跳过。

指标用复权 OHLC 的比值，交易用未复权价格。复权序列整体乘以一个常数不会改变选股比值；预测均线再通过截至昨日的复权/原始价格比例映射回昨日真实价格单位。**未来复权事件带来的统一尺度变化不进入绝对价格交易决策。** 测试覆盖了这种尺度不变性。

买单预先有效时，低开破线仍可能成交。程序保留这种亏损风险，不会因为今天最终破线而删掉订单。诊断项 `fills_below_predicted_ma` 统计这类成交。

当日发生除权，默认不直接沿用昨日真实价格尺度的买单；该日新买入跳过。该事件在当日已经生效，不是通过将来的股价筛选股票。旧持仓按公司行动结算规则处理。

## 6. 卖出、涨停续持与仓位

`execution.exit_mode` 可设为：

- `next_open`：下一交易日开盘卖出，默认。
- `next_close`：下一交易日固定收盘退出，用于对照。

没有实现“全天最高点卖出”“盘中回撤 2% 止盈”等规则，因为日线不能确定盘中路径；也没有把高开卖半仓与盘中找高点的主观描述伪装成精确复现。

`hold_open_limit_up=true` 的日频解释：

1. 次日开盘处于涨停，且没有已经生效的强制退出标记，继续持有。
2. 如果收盘后发现当天最低价低于涨停价，说明当天曾开板，给下一个交易日打上退出标记。
3. 下一交易日按既定退出方式尝试卖出。

这会比分钟开板即卖更迟。它不会利用当天最低价在当天开盘卖出。若连续整日涨停，可以继续持有。设为 `false` 可得到更简单的隔日退出对照组。

`max_holding_sessions` 默认空值，不主动限制连续涨停持仓；设正整数会改变战法含义，应单独记录。跌停、停牌或股份尚未可卖时，即使超过限制，也不能虚构卖出。

日新增预算取以下三者最小值：前日净资产×每日比例、开盘结算后的可用现金、现有持仓以外的仓位额度。单只预算默认不超过前日净资产的 10%，每日最多五只。手续费也占用预算。

默认不使用旧仓当日卖出的资金增加当日新买预算，不把未成交仓位重新分配给其他股票，不摊薄旧仓，不允许当天卖出后买回相同股票。买入为 100 股整数倍。无法买到一手时跳过。

## 7. 训练、验证、测试与调参

完整配置中：

```json
"periods": {
  "train": ["2020-01-01", "2023-12-31"],
  "validation": ["2024-01-01", "2024-12-31"],
  "test": ["2025-01-01", "2026-10-15"]
}
```

修改成你需要的日期。三段必须依次排列、互不重叠；区间中的非交易日由交易日历处理。结束日必须早于上海时区的今天，以免读取未完成或未更新的当日日线。

`warmup_sessions` 是每个数据块之前用于计算指标的交易日数，不是收益评价区间。默认 180 天。若增加均线、二波等窗口，程序会检查预热长度是否足够。

这里的“训练”是规则参数选择，不是训练机器学习模型。调参流程：

1. 仅在训练段比较 `research.grid` 指定的组合。
2. 默认要求至少 20 笔卖出成交，否则样本不足，不能入选。
3. 按 `年化收益 − 2×最大回撤` 排序，取前三个进入验证段。
4. 在验证段按同一目标选定一个组合，保存 `selected_config.json`。
5. 冻结后只跑一次测试段，不根据测试表现自动再调参。

目标函数位于 `score`，可以改为你认可的标准。默认网格只有买价上浮三个档位和涨停续持两个档位，共六组。可添加 `strategy.*` 或 `execution.*` 参数，每次最多 64 组。不要一次穷举所有阈值。

各段以独立初始资金开始，不继承上一段仓位。最后一个交易日不新开仓，未退出的旧仓仍按最后市值计价并单列，后续区间价格不用于结算前一区间。没有标签跨边界的读取。

**本版实现固定训练/验证/测试与网格选择，没有自动滚动训练功能。** 若未来需要“每三个月重选参数”，应再增加滚动实验驱动器，不应假称当前已经实现。

这些历史区间可能已被原作者或研究者观察过，只能称为历史留出检验，不等于对战法真正未知的未来。测试过后反复调整并再看同一测试段，也会造成测试集过拟合。

## 8. 成交、制度与公司行动的限制

- 成交量、涨跌停、滑点、最低佣金全部影响最终结果。
- 开盘涨停不假定买得到；开盘跌停保守不卖出，即使当天后来开板。
- 仅支持成熟的沪深主板普通 A 股，持仓期间若转 ST 按历史 ST 字段采用普通 5% 限幅模型；不支持特殊停复牌首日不设限等全部例外制度。不能用当天最终涨跌幅事后排除交易；若研究范围含特殊制度日期，应补充独立的制度数据后再回测。
- BaoStock 官方文档说明，除权日的 `preclose` 是交易所公布的除权除息参考价，并非昨日实际收盘。本程序使用该字段，按普通制度和四舍五入推算限价；不会用今天收盘反推开盘条件。由于接口没有独立的涨跌停价字段，仍不能称为逐日交易所限价的独立核验数据。
- 现金分红按除权日形成应收款，支付日变成现金。默认固定 20% 股息税假设，只是隔夜短持仓的简化；实际税收扣缴时点、持有期差异没有精确复现。
- 送转股记录锁定，到账上市前不能卖出。零碎股份、配股、复杂重组、无法核对的除权变化会报错停止，而不是算出错误收益。
- 公司行动在持仓发生复权变化时才查询，只用于相应日期的账户结算，不进入此前的选股或买入排序。
- 未卖出持仓按市值进入净资产；应收股息也作为资产计入。不能只统计已卖出的盈利而忽略被迫持有的亏损。
- 卖出成交可能是部分退出，因此胜率、盈亏比、前五大收益贡献按“卖出成交笔”计算；没有把它们命名为完整闭合交易胜率。

费率表按历史日期分段，当前默认演示覆盖 2015-08-01 起：佣金万三、每笔最低 5 元；印花税和过户费通过配置表选择相应区间。请按实际券商收费调整；若佣金报价包含某些费用，避免重复计费。本项目的表格是研究配置，不是券商账单复现。

## 9. 内存、性能与数据完整性

每次读取一个时间分段，默认三个月，并附带指标所需的预热日线。先逐只请求股票，取得当前块后在内存进行交易模拟，完成后释放；不会将多年的全市场行情同时保存在内存里。

`chunk_months=1` 可以降低行情驻留内存，但会增加接口请求和重复预热读取。调参的多个组合共享当前块行情，避免每个组合重新请求一次。进程中的历史净值、交易日志和应收股息等小型结果会保留。

全市场长历史仍可能耗时较久。免费接口不是无限速服务；项目采用串行读取、请求间隔和有限重试，不进行高并发抓取。小股票池检查通过后再扩大范围。

股票全集来自 `query_stock_basic`，不按今天仍在上市的状态过滤，保留数据源提供的历史退市股票；每日 ST 来自历史日线，不用今天股票名称判断过去。

供应商是否收录所有退市公司，仍需独立检查。自行指定股票池会引入选择偏差。当前不是经机构审计的数据质量保证。

接口报错、原始与复权日期不一致、应有交易日缺数据、持仓消失等情形直接停止，不把问题当作“没有信号”忽略。该策略较保守：某些数据源未提供的停牌日可能需要补充独立停牌接口后再处理，不能盲目向前填充。
